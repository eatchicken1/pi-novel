# Story Analysis

## 固定流程

1. 调用 `read_story_context`，按问题定向读取项目资料和章节摘要，不加载全部正文。
2. 区分文本事实、结构推断和修改建议。
3. 从因果链、人物欲望、冲突升级、信息分配、节奏和结局回报六个维度分析。
4. 输出可执行的修改优先级；分析结果默认不是正史。
5. 只有用户确认后，才用 `save_story_document` 将分析或修改决策保存到项目资料。

## 完成条件

- 每个主要判断都能指向具体章节、摘要或结构化事实。
- 建议与已确认设定分离，不直接改变 story bible。
